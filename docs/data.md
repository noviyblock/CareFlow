# Данные

Пайплайн: `uv run dvc repro` (стадии `download_*` → `prepare_*`), источники и sha256 в `configs/data.yaml`, результат в `data/processed/<dataset>/{train,valid,test}.jsonl` + `stats.json`. Схема: `src/careflow/data/schema.py`.

## ESConv

- Источник: HF `thu-coai/esconv`, ревизия `32c54c15`, CC BY-NC 4.0.
- **1300 диалогов** (в статье ACL 2021 — 1053; это расширенный релиз). 38 365 реплик, в среднем 29.5 на диалог, максимум 120.
- Сплит: официальный thu-coai 70/15/15 → 910 / 195 / 195. Принадлежность восстановлена по содержимому, совпали все 1300, пересечений нет.
- Стратегии supporter: 8 классов Helping Skills, сильный дисбаланс (Question 3801 … Restatement 1089).
- Оценки seeker по ходу диалога (`feedback`, 1–5): 7681 оценка; в **166 диалогах** есть оценка ≤ 2.

### ⚠️ Финальная интенсивность не даёт контраста

- У 150 диалогов нет `final_intensity`.
- У всех остальных 1150 **интенсивность снизилась минимум на 1** (Δ=1: 417, 2: 433, 3: 193, 4: 107). Релиз, по-видимому, отфильтрован по успешным диалогам.
- Следствие: `initial − final` нельзя использовать как метку «поддержка не сработала» и как контраст для детектора аномальной динамики. Контраст берём из (а) оценок `feedback` ≤ 2 по ходу диалога, (б) синтетических сценариев эскалации, (в) adversarial-кейсов HEART.
- Также: если «нормальная» траектория в ESConv — всегда снижение, то детектор «слишком быстрого перехода к позитиву» нужно калибровать по *скорости* снижения, а не по факту.

## EmpatheticDialogues

- Источник: архив Meta `empatheticdialogues.tar.gz`, CC BY-NC 4.0.
- **24 850 диалогов**, 107 220 реплик, 4.3 реплики на диалог (максимум 8), 32 эмоции.
- Сплит: оригинальный 19 533 / 2 770 / 2 547.
- Особенность формата: запятые в тексте экранированы как `_comma_`; в valid/test ~половина строк имеет 9-е поле без заголовка (кандидаты ответов) — отбрасываем, как ParlAI.
- Роль seeker = автор ситуации (первая реплика). Диалоги короткие: для многотуровой динамики годятся слабо, используем для сравнения с InsideOut.

## Эксперимент `esconv_dynamics` (2026-10-20)

Run: [MLflow](https://dagshub.com/noviyblock/CareFlow.mlflow/#/experiments/1/runs/f4ca0ae1721c4756b81a5cb9daf81247), конфиг `configs/experiments/esconv_dynamics.yaml`. Классификатор `j-hartmann/emotion-english-distilroberta-base` (Ekman + neutral) по 19 990 репликам seeker, все сплиты ESConv. Анализ описательный (exploratory), поправок на множественные сравнения нет.

| Метрика | Значение |
|---|---|
| Доля меток: neutral / sadness / joy / fear / surprise / anger / disgust | 0.39 / 0.21 / 0.18 / 0.07 / 0.06 / 0.05 / 0.04 |
| Средняя уверенность классификатора | 0.74 |
| De-escalation (полярность в конце выше, чем в начале) | 0.65 |
| Escalation | 0.09 |
| «Too fast» (neg → pos за 1 реплику) / «stuck» (3 последние neg) | 0.053 / 0.008 |
| **Proxy validity:** Spearman ρ(Δполярности, Δсамоотчёта интенсивности), n=1150 | **0.06** (p=0.04) |
| Самая длинная серия neg: диалоги с feedback ≤ 2 (n=166) vs остальные (n=1134) | 3.11 vs 2.82, Mann–Whitney p=0.038 |
| «Stuck»: feedback ≤ 2 vs остальные | 0.018 vs 0.006 |

**Выводы:**
1. **Готовый классификатор эмоций по репликам — слабый прокси состояния пользователя.** Его изменение почти не связано с тем, что пользователи сами сообщают об интенсивности (ρ = 0.06). Ограничения сравнения: самоотчёт имеет суженный диапазон (Δ ≥ 1 везде), полярность грубая (−1/0/1). Тем не менее детектор sycophancy «по аномальной динамике» на этом сигнале строить нельзя: нужен более точный сигнал состояния (регрессия интенсивности, appraisal через LLM или модель, дообученная на оценках `feedback`).
2. **Слабый, но значимый контраст:** в диалогах с низкой оценкой пользователь дольше остаётся в негативе, и «застревание» там в 3 раза чаще. Это в пользу гипотезы RQ4, но эффект мал, тест один и не скорректирован.
3. Возможный артефакт (не проверено): высокая доля de-escalation может объясняться ритуальными «спасибо, пока» в конце диалога, которые классификатор относит к joy. Проверить, исключив последние реплики.

## HEART (релиз GitHub `Hippocratic-AI-Research/HEART`, коммит `c3387b43`, Apache-2.0)

- Выложено: 280 обычных + 20 adversarial контекстов, по 3 человеческих ответа на контекст, ответы ~20 моделей (в т.ч. frontier), промпты трёх judge (gpt-4o, claude-sonnet-4, gemini-2.5-flash).
- **Не выложено: человеческие попарные оценки** (в статье — 42 000 сравнений, 15 оценщиков). Поэтому напрямую проверить наш judge на людях HEART нельзя.
- ⚠️ **HEART построен на ESConv.** 240 из 300 контекстов делят с ESConv ≥ 2 длинные (> 40 символов) реплики: 166 — с train, 34 — с valid, 40 — с test (107 из них — дословный префикс диалога ESConv).
- **Правило против утечки:** при оценке на HEART исключаем (или отчитываемся отдельно по) контекстам, пересекающимся с ESConv train, если система/роутер/студент обучались на ESConv train. Скрипт проверки пересечения — в этапе 3/4.
