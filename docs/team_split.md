# Разделение работы (черновик для согласования, 2026-10-29)

Цель — одна общая система и статья без дублирования. Стыки зафиксированы как форматы данных.

| Блок | Кто | Что отдаёт другим |
|---|---|---|
| Детекторы сигналов пользователя: негативные эмоции, недовольство помощником (FailedESConv, EmoWOZ, Client Reactions, ruptures) | коллега | функция `score(context) -> {neg_emotion: p, dissatisfaction: p}` + размеченная выборка с train/valid split |
| Роутер, переключающий стратегию по сигналу (эмоции vs недовольство) | коллега | решения роутера по репликам: `switch: bool`, причина |
| Протокол оценки: judge по рубрике HEART, валидность judge, сигнал состояния, задержка (wall-clock, токены, AGL/AROL), позже sycophancy | мы (CareFlow) | `eval(responses) -> win-rate, CI, latency` для любой системы |
| Бейзлайны генерации и мультиагентные схемы: single-agent, planner–generator–critic, InsideOut, debate | мы | ответы систем на общей выборке контекстов |
| Инфраструктура: данные в DVC, MLflow на DagsHub, кэш LLM, локальные модели с фиксированными ревизиями | мы | общий репозиторий и конфиги |

**Точки пересечения (делаем вместе, а не параллельно):**
- Общая выборка контекстов ESConv (наш сплит, `data/processed/esconv`), чтобы результаты были сравнимы.
- Роутер коллеги оценивается нашим протоколом: качество (judge) × задержка × лишние переключения / пропущенные жалобы (его метрики).
- Разметка недовольства коллеги — внешняя проверка нашего сигнала состояния (E1) и judge.

**Открытые вопросы к коллеге:** источник FailedESConv (ссылка/ID и лицензия); точные ссылки на EmoWOZ, Client Reactions, работу о ruptures; полнота разметки (проверены только положительные метки: точность 90%, полнота неизвестна); доступ к серверу 6×A6000 и деление GPU.
